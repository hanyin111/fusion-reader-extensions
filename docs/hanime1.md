# Hanime1 動畫 v1.1.0

2026-10-14 核对官网 `http://hanime1.me/` 的公开页面，完成单文件插件。只读取匿名可访问的分类、搜索、详情和播放地址，不登录、不写入网站数据、不调用广告或统计接口。

## 使用前提：本体必须真的在用代理

站点的 Cloudflare 边缘会拦截直连请求。用本体同款网络栈（dio + CookieManager + IOHttpClientAdapter）实测同一条搜索与视频地址：

| 路由 | 结果 |
| --- | --- |
| `findProxy` 指向代理（`PROXY 127.0.0.1:7890`） | 200，页面完整可解析 |
| `findProxy` 为 `DIRECT`（本体没读到代理） | 403 `Attention Required! \| Cloudflare` |

聚阅本体的代理只来自**进程环境变量**（`lib/services/network.dart` 的 `resolvedProxy()` 依次读 `HTTPS_PROXY`、`https_proxy`、`HTTP_PROXY`、`http_proxy`）。代理工具的「系统代理 / 规则模式」不会写这些变量，因此本体会以直连发出请求并收到上面那张 403 页面；播放器（libmpv）的 `http-proxy` 也取自同一个变量，需要一起设置。

桌面端（Windows / macOS / Linux）任选一种：

```powershell
# 永久（当前用户），之后要完全退出本体再重新打开；必要时注销重登让新环境变量生效
setx HTTPS_PROXY "http://127.0.0.1:7890"
setx HTTP_PROXY  "http://127.0.0.1:7890"

# 或临时：在同一个终端里设置后再启动本体
$env:HTTPS_PROXY='http://127.0.0.1:7890'; $env:HTTP_PROXY='http://127.0.0.1:7890'
& "C:\path\to\fusion_reader.exe"
```

也可以把代理工具切换到 **TUN / 系统级 VPN 模式**，让所有进程的流量都经过它。

Android / iOS 上本体读不到环境变量（`Platform.environment` 基本为空），需要让代理 App 以 **VPN 或透明模式**接管全部流量后使用。

v1.0.1 的变化：读取被拦截时先自动重试一次，仍失败则给出上面的原因与处理办法，而不是只抛一个状态码；随后 30 秒内不再连续请求站点。

## 可行性结论

站点本身适合做分类来源：分类、标签、排序、日期过滤都是服务端渲染的 GET 参数，视频页直接内嵌带签名的 mp4 地址（480p / 720p / 1080p），作品与播放清單的关系在页面上明确给出。两个需要专门处理的地方：

- **传输**：站点的 Cloudflare 边缘对「非浏览器 TLS 指纹」的直连 https 请求直接返回 `Attention Required!`（403）。实测聚阅本体使用的 dart:io 客户端、node 的 fetch、Python 的 urllib 都被拦，而站点自身的 http → https 跳转链路正常：http 请求返回 301，跟随跳转后的 https 请求返回页面。所以插件的页面请求统一走 `http://hanime1.me/...`，由本体客户端跟随跳转；媒体域名 `vdownload.hembed.com`（CDN77）不在该边缘后面，https 直连正常。
- **两套卡片结构**：搜索 / 标签 / 播放清單页是横向卡片（`video-item-container`），类型页（`genre=`）是网格卡片（`home-rows-videos-div`）。两种都在脚本内解析，并按文档顺序合并、按影片编号去重；广告卡片因为链接不指向 `/watch?v=` 被自然过滤。

## 已支持

- 48 个分类入口：10 个类型（裏番、泡麵番、新番預告、2D動畫、3DCG、2.5D、MMD、Motion Anime、Cosplay、AI生成）、9 个排序（最新上市、最新上傳、本日/本週/本月排行、觀看次數、讚好比例、時長最長、他們在看）、23 个标签（中文字幕、無碼、AI解碼、中文配音、同人作品、1080p、60FPS、ASMR、斷面圖，以及常用角色与题材标签）、6 个发布日期区间。
- 分类、搜索分页；标题、封面、时长与播放量作为列表摘要。
- 关键词搜索，以及详情页作者入口按上传者姓名检索。
- 详情页标题、封面、作者、类型、片长、观看次数与日期、作品说明、标签（最多 20 个）。
- 作品目录：视频属于播放清單时按清單读取全部集数（页面上声明的集数不完整时明确报错，不静默截断）；不属于清單时只列出本片。
- 播放：每次播放重新读取视频页，从内嵌的 `<source>` 列表取值，避免保存会过期的 `secure` 签名地址；画质默认自动（优先 1080p，其次 720p / 480p），可在插件设置里固定为 1080p / 720p / 480p，指定的画质不存在时回退到最高可用画质。
- 读取节流：请求串行且间隔不小于 350 毫秒，相同读取合并，页面结果缓存 30 秒；遇到 403 / 429 暂停 30 秒再继续。
- 网络路由声明为 `proxy`：站点在中国大陆需要代理，媒体域名不拒绝代理出口，页面与播放共用一条线路。
- 评论（v1.1.0 新增，`@comments work`）：视频页的评论与回覆，作者、时间、正文、点赞数、回覆数、正文里的图片；回覆按父评论单独读取，进入评论页或播放器时自动显示。

## 评论接入方式

站点在视频页用 `GET /loadComment?id=<影片>&type=video&content=comment-tabcontent` 取评论，返回 `{comments: "<html>"}`；回覆用 `GET /loadReplies?id=<评论>`，返回 `{replies: "<html>", comment_id: <评论>}`。两处都只读、无需账号。

解析按站点的真实结构做：每条评论与回覆都以 `div.report-btn-wrapper` 开始，块内依次是作者与时间（`.comment-index-text` 内的 `<a>` 与 `<span>`）、正文（带 `color: white` 的 `.comment-index-text`）、带 `data-reportable-id` 的上报按钮、点赞数（`thumb_up` 后的数字）、回覆按钮里的「N 則回覆」，以及正文中除加载图标以外的图片。评论与回覆共用同一套解析，回覆由本体的父评论参数触发。

这一版的边界：

- 接口**没有分页**，一次返回该视频的全部评论，所以 `hasMore` 恒为 `false`，请求第 2 页会返回空列表而不是重复内容。
- 只能读、不能发；登录后才有的操作一律不做。
- 点赞数取自页面上的数字（未登录时站点对 0 赞隐藏数字，按 0 处理），不做推断。
